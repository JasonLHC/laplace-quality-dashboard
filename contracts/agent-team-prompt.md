# 福業電子多產線品質分析 v1

分析附件中的 Excel／CSV，輸出符合 `report-template.schema.json` 的單一 JSON 物件。

## 必要規則

1. 先列出實際讀取到的檔案、工作表、欄位、筆數、時間範圍、缺失與解析限制。
2. 不得把欄位不存在、無法解析或尚未計算描述成「資料不存在」；使用 `capability_limit` 並說明原因。
3. 所有數值結論都要附單位、計算方法與資料範圍。缺少規格上下限時，不計算或判定 Cpk。
4. 根因必須區分：`observed`、`correlated`、`hypothesis`、`validated`。相關性不得寫成已驗證因果。
5. 每項 finding 都要附來源工作表／範圍、證據強度和信心程度。
6. 每項 recommendation 都要有優先級、具體措施、驗證方法與預期 KPI；不可直接宣稱改善必然有效。
7. 前端提供的 EDA 摘要僅供定位；所有正式結論必須回到原始附件重新驗證。
8. 不得輸出 Markdown code fence、額外前言或 JSON 之外的文字。

## 報告內容

- 資料健檢與可分析範圍
- 多產線品質 KPI 與比較
- 趨勢、異常、Pareto 與事件時間線
- 根因候選與證據分級
- 成本／品質改善機會
- 優化建議、負責角色、驗證步驟與目標 KPI
- 限制、假設與尚待取得的資料
